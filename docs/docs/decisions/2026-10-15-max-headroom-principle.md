# 决策：兜底原则（最大余量 / maximum headroom）

- **日期**：2026-10-15
- **状态**：✅ 已确立（本会话由用户拍板；后续所有性能/架构决策须对照本条）
- **标签**：`#架构 #原则 #性能 #健壮性`

## 核心表述

> 系统对操作人员的承诺不是"平均够快"，而是**最坏情况下没有墙**；
> 任何降级、任何跳过、任何"做不到"，都必须**可见**。

不是"用低廉的实现成本获取可换取的性能"（成本-收益交叉点策略），
而是**用尽可能高的兜底能力，不让操作人员感到痛苦**。

## 测量依据（本机 Zen 1 单核，2026-10-15 实测摘要）

| 场景（10⁵ 行） | 耗时 | 判定 |
|---|---|---|
| `(A-B)/(B+1)` 逐元素 | 0.17 ms | TS 足够 |
| 5 个超越函数/行 | 9.6 ms | TS 尚可 |
| 20 次 Newton 迭代/行 | 41.7 ms | TS 边缘，必须异步化 |
| GEMM 1024² | 1175 ms（ml-matrix ≈ 1.9 GFLOPS 上限） | 原生/WASM 主场 |
| 运输地板（3.05 MB，localhost，零计算） | 8.5 ms | 原生后端对逐行公式的增益上限 |

- 判别量是**算术强度**（ns/行，10⁵ 行时门槛 ≈ 85 ns/行），不是"公式看起来多复杂"。
- 逐行公式走原生后端受**运输地板封顶**（≈1–5×）；WASM 无运输，重算术更优。
- 矩阵公式（`eig`/`svd`/`inv`/`A\b`）是原生主场：O(n³)、数据小。
- 浏览器侧真正的规模天花板是**内存驻留**（10⁷×10 列 ≈ 800 MB 紧张；10⁸ 不可行），
  不是算术速度。
- ⚠️ Eigen 20–24 GFLOPS 为按官方基准归一化的**推导值**（本机无 C++ 工具链，未实测）；
  JS 侧 2 GFLOPS 天花板为实测。

## 结论：三层 + 三个契约

**操作人员永不选择层**。分层是实现细节，产品只承诺"没有墙"：

| 层 | 载体 | 角色 | 移除哪堵墙 |
|---|---|---|---|
| T1 | 浏览器内 TS | 常见情形，毫秒级反馈 | —（基线） |
| T2 | WASM SIMD（worker） | 重逐行算术，**零运输** | "太慢" |
| T3 | 原生后端 | 大内存 / 算法逃生舱（SciPy / Octave / Eigen） | **"做不到"**、"装不下" |

三条硬性契约：

1. **降级必须可见**——T3 不可用 → 降到 T2/T1，并明说降级了什么；
   禁止静默变慢、静默报错、静默改语义。
2. **层间语义一致**——同一公式在任何层给出同一结果；
   **跨层共享测试夹具 + 差分测试**是硬要求，先于引擎实现（夹具先行）。
3. **最坏情况有界且可感知**——宁可 5 分钟带进度条，不可 5 秒冻结；
   冻结本身就是"痛苦"。

## 与其他原则的对比：矛盾与权衡

| 已有原则 | 关系 | 矛盾 / 权衡点 | 解决方式 |
|---|---|---|---|
| **严格分离**（表永不改写） | 一致，需细化 | T3 持有数据副本；浏览器副本被丢弃后，编辑可能分叉，破坏单一事实源 | 后端持有的是**不可变缓存**；编辑永远产出新卡。原则不变，只补缓存语义 |
| **卡片模型 / 节点独立**（缺陷 C 暂缓的依据） | 一致 | 每个节点独立持有全量列（C）与 T2/T3 的内存天花板相撞 | 节点独立是数据模型原则，**不让步**；内存问题靠分块/流式 + 后端存储解决，**不靠合并节点共享引用** |
| **列式矩阵、高性能** | 主从关系 | "高性能"原是独立目标；兜底原则把它降级为**避痛的手段** | 追极端最坏情况（10⁷–10⁸ 行）撞上内存数组上限时，数据模型要能表达"大文件的视图"，而不只是"内存中的数组"——这是待解的最大结构张力 |
| **连线从属**（连线不约束布局） | 一致，是具体约束 | 兜底可视化（进度、取消、降级提示）不得破坏卡片模型 | 进度/取消长在**卡片自身**；不做约束画布的模态弹层 |
| **可扩展**（社区长尾） | 互补，但更严 | 插件越多，NaN/舍入语义分歧越多 → "层间语义一致"契约越严 | 插件契约必须**声明自己的 NaN 语义**并接入共享夹具 |
| **先用户视角，再技术方案**（vault 约定 2） | 一致，是极端形式 | — | "用户的痛"就是最坏情况分布的尾部；本原则是该约定的具体化 |

**被否掉的替代路线**（本次作废的论证口径）："找性能交叉点划线——线之上做后端，
线之下留在 TS。"那是优化中位数的成本策略。兜底原则下，**任何能撞墙的路径都必须有
后备，后备必须可见**；交叉点只是*自动升级边界画在哪*的实现细节，
不是"要不要建后备"的论据。

## 反模式：静默失败（本原则点名要治的）

本项目已出现多条同类问题：

- 解析缓存按文件名键控 → **昨天的曲线顶着今天的标签**（2026-10-15 修复 B）；
- 热力图把"未定义的相关系数"画成 0（白色）→ 语义从"无法定义"变成"不相关"（第二轮审计修复）;
- `&&` 写在优先级表里但词法器从不产出 → 多条件筛选**静默不可用**；
- 工作区快照只从图表卡重建依赖 → 公式卡依赖**重载后静默丢失**；
- 显式 X 轴是冻结快照 → 换文件后曲线画在**旧文件的自变量**上，无提示。

**评审标准**（对任何新路径问三个问题）：
*它在什么情况下会失败？失败时操作人员看得见吗？降级时它显示什么？*
