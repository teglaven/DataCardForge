# 决策：表达式列引用语法 —— 名称可写、能带限定、全角可用

- **日期**：2026-10-28
- **状态**：✅ **已实施**（后端引擎、TS 差分参考、xlayer 夹具、帮助界面两侧同版）
- **标签**：`#表达式 #语法 #差分裁判 #公式卡`
- **配套文档**：[后端拥有计算](./2026-10-17-backend-owns-compute.md)、
  [卡片数据结构 v2](./2026-10-26-card-schema-v2.md)

## 核心表述

> **一列能用它自己广告出来的任何一个写法被引用，写不出来的名字用方括号括起来。**
> `Pos.1`、`pos.1`、`时间_秒`、`[地面速度_μm/s]`、`A.pos.1` 都指向同一条数据列；
> 全角标点（`（）`/`，`/`×`/`／`/`－`…）按 ASCII 等价物处理；两套引擎（C++ 生产路径、
> TS 差分基准）必须对每个字符、每条错误码、每个错误位置给出**同一个答案**。

## 背景：一句话说不清的错

用户在一个 `01_seismic.txt`（表头 `时间_秒 / 地面速度_μm/s / …`，5000×5）上点开公式卡，
默认表达式 `时间_秒 * 2` 直接报错：

```text
无法识别的字符「{char}」 (第 0 个字符)
```

三个独立缺陷叠在一起，缺一个都不会这么难看：

| # | 缺陷 | 实证 | 后果 |
|---|---|---|---|
| 1 | 词法器只认 ASCII 标识符 | `backend/src/expression.cpp` `isIdentStart` | 中文列名第 0 个字节就 `unexpectedChar`；而卡片广告的就是注解名 |
| 2 | 带表头列只注册了 `Pos.1 名称`、`1 名称`、`名称` 三个键，**唯独没有 `Pos.1`** | `buildColumnMap`（`label()` 把位置名和注解拼成一串） | “`Pos.N` 也可引用”的注释承诺对**任何带表头文件**都是假的——于是没有任何名字可用 |
| 3 | 错误参数没上路 | `nodes.cpp` 只回传 `position` | 界面把 `{char}` / `{name}` 原样打印，用户拿到一句无法行动的话 |

第 2 条是决定性的：它不是“不好用”，而是 `Pos.N` 这条官方退路也断了，等于公式卡对
**所有带表头的科学数据**不可用。第 1、3 条只是让它看起来像“语法太偏”。

## 语法（实现与帮助界面同版）

| 写法 | 含义 | 备注 |
|---|---|---|
| `Pos.1` / `pos.1` / `POS.1` | 列位置名 | 大小写不敏感；**永远可用**，不依赖名称能否拼写 |
| `时间_秒` | 注解名（裸标识符） | 允许字母、数字、`_`、`.`、任何非 ASCII 字符 |
| `[地面速度_μm/s]` | 方括号引用，内容**逐字**保留 | 名字含 `/`、空格、括号、全角符号时的唯一写法；`［］`/`【】` 同样接受，两端空白裁掉 |
| `A.pos.1` / `A.时间_秒` / `A.[…]` | 端口限定 | 字母按输入端口声明顺序（A、B、C…），端口 id（`src`、`x`、`y`）同样可用，均大小写不敏感；只有一个矩阵输入时可省略 |
| `（时间_秒 ＋ 1）× 2` | 全角标点 | `（）`→`()`，`，`/`、`→`,`，`×`/`＊`→`*`，`／`/`÷`→`/`，`－`/`−`→`-`，`％`→`%`，`＝`→`=`，`＞`/`＜`/`≠`，`　`→空格 |

## 实现要点

1. **逐字符映射，不重写输入。** 全角标点在词法器分类的那一步换成 ASCII 运算符；不做全文
   归一化，否则 `[温度（℃）]` 这类名字会被改写。
2. **`0x80` 以上的字节都是名字字节**，两套引擎同样处理，不引入 Unicode 表。结构标点
   （全角运算符、方括号）在扫描名字时排除——这条顺序是必须的：全角字形也是 ≥0x80，
   若先走标识符分支会被吞掉并**死循环**（实测挂死三个请求，已加空标识符硬保护）。
3. **列名键表**（`buildColumnMap` / `compile()`）：完整标签、`pos.N`、`N`、裸注解；
   端口限定键（`a.pos.N`、`a.注解`、`a.完整标签`）由别名区间追加。全部“加法式、先到先得”，
   已有可解析表达式行为不变（唯一有意保留的旧行为：重复标签仍后到覆盖）。
4. **`A.[名字]` 在词法层拼成一个名字**，解析器不需要知道限定写在括号外面。
5. **错误参数结构化**：`ExpressionError` 携带 `detail`，节点层按 code 回传
   `char` / `name` / `token` 与 `min` / `max` / `expected` / `got`，界面据此本地化，
   不再打印占位符。位置改为**码点计数**（TS 侧是 UTF-16 单元，BMP 内一致），
   中英混排时报错位置才对得上。
6. **默认表达式必须可拼写**：新建公式卡的默认 `名称 × 2` 里，名称用给用户看的注解，
   表达式里的引用只有在能拼写时才用注解，否则退到 `Pos.N`（`workspaceStore.ts`
   `formulaReference`）。否则默认公式就是一次演示失败的示范。
7. **差分裁判扩充**：`web/tests/fixtures/xlayer/expression.v1.json` 增加中文列名、
   带表头 `Pos.N`、方括号、全角标点与两个错误用例；vitest 与 ctest 跑同一份 JSON。

## 已知取舍（明确不做）

- **数字名的死路**：`1` 永远是数字字面量，不会解析成“第 1 列”。所以 `Pos.N` 是唯一稳定
  的数字写法；测试里已锁定这一点，防止有人“修好”成遮蔽字面量。
- **未闭合方括号**报 `expectedClose`（复用现有错误码，文案「缺少右括号」），不新增
  `unclosedBracket`：新增码要同时改中英字典，收益不抵成本。
- **全角数字**（`１２３`）不被当作数字；需要就用半角，或用方括号包成名字。
- **名字里含全角结构标点**（如 `温度×`）必须用方括号；裸写会被当成运算符。
- **矩阵卡模式**（`evaluateMatrix`）只沿用新词法器，不做 `Pos.N` 别名——矩阵卡用的是显式
  变量名，没有位置名概念。

## 测试

- `backend/tests/nodes_test.cpp`：带表头矩阵走**真实节点路径**（v1 表达式节点与
  `builtin:expression-columns` 两条求值点）验证四种写法 + 三种结构化错误参数。
  两条路径都测，是因为 `A.pos.1` 曾经只在 v1 路径可用、在用户真正用的公式卡上失效。
- `web/tests/expression.test.ts`：写法表、限定引用、错误参数。
- `web/tests/fixtures/xlayer/expression.v1.json`：两套引擎的共同裁判（81 例）。
- `web/scripts/smoke.mjs`：真实浏览器里建一张公式卡，断言表达式行可见、能算出列、
  `Pos.N` 引用可算——公式卡此前没有任何 e2e 覆盖。
