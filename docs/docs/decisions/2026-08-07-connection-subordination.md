# 决策：连线从属原则

- **日期**：2026-08-07
- **状态**：✅ 已确定
- **标签**：`#架构 #可视化 #连线`

## 核心表述

> 卡片是主角，连线是配角。

连线仅为数据依赖的可视化（元信息），**常态低调（背景层），不干扰卡片布局与交互**。

## 派生的具体规则

| 规则 | 说明 |
|------|------|
| 连线永远在卡片之下 | 背景层绘制，不遮挡内容、不拦截鼠标 |
| 布局不受连线约束 | 卡片可任意停靠/拖拽，连线**跟随并绕行**，绝不反推卡片移动 |
| 常态低调 | 未选中时灰色细线，不抢注意力 |
| 选中才强调 | 选中卡片 → 其连线变亮/变粗（仍在背景层） |
| 端口标记兜底 | 卡片边缘圆点，遮挡时仍可追踪进出点 |
| 密集时降级 | 连线太多可折叠成"依赖列表"面板 |

## 为什么成立

1. **卡片驱动**的产品里，卡片承载内容，连线只是关系；让连线约束布局 = 配角绑架主角
2. 这条原则**连锁解决**了 WebView 分层难题——线住背景层，WebView 只是普通卡片，绕行即可，无需 OSR / 透明覆盖层 / 多窗口层
3. 与"严格分离"哲学一致：连线是数据流（数据），卡片是内容（表现）

## 与现状的差异（待后续对齐）

当前 Qt `ConnectionOverlay` 仍是"高亮线置顶"的双覆盖层模型。按此原则，未来应改为：
- 背景层曲线 + 绕行卡片矩形
- 端口标记
- 仅"选中卡片的被遮挡连线"这一种情况临时置顶
