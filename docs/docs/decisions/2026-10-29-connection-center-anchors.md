# 决策：连线端点落在卡片中心 —— 单条三次贝塞尔 + 流动虚线

- **日期**：2026-10-29
- **状态**：✅ 已实施（卡心端点、单贝塞尔与权重混合、出卡点箭头、可见段标签、整卡跳变补间、红蓝流动虚线）
- **标签**：`#前端 #连线 #几何 #无障碍`
- **上游决策**：[连线从属原则](2026-08-07-connection-subordination.md)、
  [端口级连线](2026-10-28-port-level-connections.md)（本决策**修正**其「决策 3」与「不变量 2」）

## 核心表述

> 连线的两个坐标是**两张卡片窗口的中心**，卡片内部交给遮罩吞掉；
> 一条三次贝塞尔就是整条路线，最多两个拐点；
> 红蓝不再是只靠颜色区分的实线，而是**朝着数据方向流动**的长/短虚线。

## 背景（这一轮修的是什么）

2026-10-28 的端口级连线把端点钉在端口芯片上。端口身份是对的（`portId` 是数据身份，不按位置），
但把它当成**几何锚点**之后：

| 现象 | 原因 |
|---|---|
| 线总是从卡片右侧中部挤出、从左侧中部扎入 | 端点固定在端口/朝向边中点，卡片另外三边永不出现线 |
| `表→函数卡→图表` 的三段线在右侧挤成一束 | 每段都被拽到同一侧 |
| 箭头指向"某个 chip"，而不是"数据进了这张卡" | 箭头画在端口上 |
| 红蓝之外没有第二条编码 | 只靠颜色区分输入/输出，色觉障碍不友好 |

用户的要求是：从卡片里"流"出来、被窗口遮住、一根平滑曲线（拐点太多会乱）、
移动窗口时轨迹平滑变化（变化途中若经过别的窗口就快速通过）、红蓝改成流动虚线以便兼顾色觉与
快速分辨输入输出。

## 决策内容

1. **端点 = 卡心。** `useConnectionGeometry` 用 `cardRect()` 的中心做两端，
   `portAnchor` / `cardAnchor` **不再参与几何**。卡片内的那一段由现有 mask（每张卡一个黑洞）
   自然抹掉，可见段从卡片边框开始 —— 这就是"被窗口遮蔽"，不需要新的遮罩逻辑。
2. **端口退为数据身份。** `portId` 仍随边传递、仍由选中标签列出；`registerPort` /
   `portAnchor` 保留但**不再影响连线几何**（留给 08-07 决策里尚未落地的"端口标记兜底"）。
   `cardMetrics` 的测量 API 不变。
3. **一条三次贝塞尔。** 两个端点固定为卡心，两个控制点由「水平解 / 垂直解」按
   `w = |dx| / (|dx| + |dy|)` **权重混合**：横排、纵排、45° 都退化成直线，斜向是 S 形。
   混合是必须的 —— 直接二选一的话，拖拽越过对角线时控制点会从 `(50,0)` 跳到 `(0,50)`，
   正是要避免的"突跳"。三次贝塞尔最多两个拐点，符合"最多两个拐点"的上限。
4. **箭头落在出卡点。** 沿曲线从末端往回采样、二分定位曲线与目标卡片边框的交点，
   箭头尖端停在边框外（卡片内会被 mask 抹掉）。整条曲线都落在目标卡内（两卡几乎完全重叠）时
   **宁可不画箭头**，也不把箭头画到卡心。
5. **标签落在可见段中点。** 几何中点经常落在某张卡里，被 mask 抹掉；改为在"最长的一段
   不被任何卡片覆盖"的中点放置，全被遮住时退回 t = 0.5。
6. **整卡跳变做补间。** 拖拽/缩放每帧位移很小（< `JUMP_THRESHOLD` = 24 平面 px），
   **直接跟随、不补间**（否则是橡皮筋滞后）；平铺/层叠/载入/撤销是一次性跳变，做 220ms
   缓出补间。若补间扫过第三张卡（既非起点也非终点），整段压到 70ms —— 线在卡下不可见，
   扫过时只剩边缘的一闪，"快速通过"是噪声最小的过法。
   补间只在运行时开 rAF：空闲零成本，延续"布局版本号驱动、非定时器轮询"。
7. **红蓝改流动虚线。** 红 = 选中卡是源（长划 10/6）、蓝 = 选中卡是目标（短划 4/5），
   两者都朝目标流动（负 `stroke-dashoffset`）。于是**颜色 + 流 + 图案**三重编码输入/输出；
   色觉障碍者不依赖颜色也能读。灰色背景线保持细实线、不流动（背景低调）。
8. **尺寸按 1/zoom 在组件里算。** 线宽、虚线段长、流动周期全部换算成用户单位
   （`strokeWidth={w/zoom}`、`strokeDasharray={d/zoom}`、`--connection-dash-cycle`），
   并去掉 `vector-effect: non-scaling-stroke` —— 它只管线宽、**管不到虚线段长**
   （[svgwg#323](https://github.com/w3c/svgwg/issues/323)），10% 缩放下虚线会连成实线。
   现在 10%–300% 下线宽与段长在屏幕上恒定。

## 不变量（改这块时不许破）

- 一对卡一条线；同一张表喂 5 列给同一张图仍是 **1** 根线，端口在标签里列出。
- 端点是**卡心**，不是端口、不是边中点、不是朝对面的边。
- 箭头必须在目标卡片**边框外**；整条线被目标卡吞掉时宁可不画。
- 连线层永不拦截指针（`pointer-events: none`），永不参与布局。
- 灰色的未选中线不流动、不加虚线。
- 拖拽中不补间（每帧跟随）；补间只在整卡跳变时出现。
- K > 1 的输出仍在卡级绘制（两个 id 空间不可混用），本决策没有改这一点。

## 未决（下一轮）

- hover / 点选单条线：要动"连线不拦截鼠标"这条锁定项。
- 删除一条线（断线）：等于改数据（`inputs[]` 与后端 `PortBinding`），需要撤回路。
- 拖拽建线：讨论里的理想态，目前仍由列面板 / 重指向确认代替。
- 端口圆点（08-07 的"端口标记兜底"）：需要第三层并处理遮挡；`portAnchor` 就是为它留的。
- 补间是"整段变速"而不是"分段变速"：分段会自己产生顿挫，若要更精细再单独裁决。
- 端口级高亮（同一张卡的多条线里指出是哪一路端口）目前只有标签，没有视觉差异化。
