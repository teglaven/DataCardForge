# 决策：画布改为无边界平面（平移，不含缩放）

- **日期**：2026-10-21
- **状态**：✅ 已确立（用户拍板："请把当前的工作台改为无限视图，否则根本装不下复杂的工作流"）
- **标签**：`#架构 #前端 #画布 #交互`
- **基线**：本决策实施前的回滚点为 tag `pre-stage3-baseline`（`03c5622`）之后的 `11f7bc4`。

## 核心表述

> **卡片平面不再等于一屏。** 卡片坐标存在于一个无边界的平面上，视口可以平移；
> 平面随卡片自动增长，新卡永远出现在看得见的地方。

## 背景

走进这个决策的原因不是"想要一个花哨的画布"，而是**当前实现主动把工作流限制在一屏内**：

| 现状 | 位置 |
|---|---|
| `.canvas` 是 `overflow: hidden` 的视口大小容器，无滚动、无平移 | `web/src/styles.css` |
| **新卡被 `placeWithinCanvas()` 强制夹回视口内** | `web/src/ui/workspaceStore.ts` |
| `Rnd bounds="parent"` 把拖拽也限制在一屏内 | `web/src/ui/components/CardShell.tsx` |
| 连线层是视口大小的 SVG（`inset: 0`），锚点按画布坐标测 | `web/src/ui/ConnectionLayer.tsx` |

第二行是**行为规则**而非布局细节：一张表停在右边缘时，从它开出的图表会被折回父卡身上
（这正是当年"图表开到画布外、状态栏却报成功"的补丁留下的副作用）。
换句话说，卡片空间的上限 = 窗口宽度，复杂工作流无处展开。

## 选项

| 选项 | 内容 | 判定 |
|---|---|---|
| A. 平移 + 无边界平面 | 视口可平移，平面随卡片增长，**不缩放** | ✅ **采纳** |
| B. 平移 + 缩放（真·无限画布） | 再加滚轮缩放 | 暂缓：需处理 react-rnd 的 scale 坐标、锚点反变换、缩放下的拖拽步长，回归面显著更大 |
| C. 保持现状（一屏） | —— | 被否：用户诉求正是"装不下" |

## 结论细则

1. **两个坐标系**：`.canvas` 是视口（裁剪、不动），`.canvas__world` 是平面（带
   `translate(-view.x, -view.y)`）。**锚点测量对世界层做差**，于是平移在几何里自动抵消，
   `cardMetrics` 不必知道平移存在——这与它原本"窗口滚动不必处理两次"的思路是同一条。
2. **平面尺寸由卡片推导**（`max(卡片右下角) + PLANE_PAD`），因此拖动卡片向外会让平面长大，
   下次还能拖得更远——"无边界"由增长实现，而不是给一个巨大的固定尺寸。
3. **新卡位置与视图的关系**：位置仍按"紧挨父卡"计算（连线因此保持短），若该处落在可视区外，
   **移动视图去就它，而不是把卡片折回来**。折回来会让图表远离它所属的表格，
   把连线拉成横穿画布的长线，破坏画布本来在讲的空间关系。
4. **平移手势**：滚轮/触控板、中键拖动、空格+左键拖动，以及空白处左键拖动（超过 4px 阈值才算平移，
   否则仍是"点空白取消选中"）。**不劫持右键**——右键已经是"新建表格/开图表"的既有手势。
5. **卡片拥有自己的滚轮**：指针落在 `.card` 内时画布不平移（虚拟表格滚动、图表 dataZoom 照旧）。
6. **网格随平移视差**：点阵背景留在视口上，用 `background-position: -view % 22` 制造随动，
   避免为背景再引入一个平面尺寸的合成层。
7. **连线层留在视口尺寸**，内部 `<g>` 反向平移。平面尺寸的 SVG 会被当作一个巨大图层栅格化，
   代价不可接受；同时掩码矩形必须覆盖整个平面（`100%` 只在视口内有效，会静默抹掉远处的线）。
8. **视图不进快照**：卡片几何仍按原样持久化，平移是纯视图状态，"重置工作区"时归零。
   菜单 **视图 → 回到卡片** 把视图重新框到全部卡片上，作为"平移到远处后找不到工作"的逃生口。

## 接受的对价（明示，非静默）

| 代价 | 表现 | 对策 |
|---|---|---|
| 无缩放 | 大工作流只能平移，不能一屏纵览 | 选项 B 已论证，留作后续 |
| 平面不向负方向生长 | 卡片坐标 ≥ 0，不能往左/上无限铺开 | `bounds="parent"` 本就如此；避免负坐标带来的原点偏移 |
| 平移不进快照 | 重新打开工作区回到原点 | 视图 → 回到卡片 一键取景 |
| 平面尺寸的合成层 | 大平面理论上更贵 | Chrome 对大图层分块栅格化；背景留在视口、SVG 留在视口，仅卡片层随平面 |

## 关联模块

- `web/src/ui/cardMetrics.ts` → 拆成 `setCanvasElement`（视口尺寸）与 `setWorldElement`（坐标原点），
  新增 `viewportRectInWorld()`
- `web/src/ui/components/CardCanvas.tsx` → 视口/世界双层结构 + 四种平移手势
- `web/src/ui/workspaceStore.ts` → `view` 状态、`panBy`/`setView`/`resetView`、
  `placeOnPlane` + `revealView`（取代 `placeWithinCanvas` 的夹取）
- `web/src/ui/ConnectionLayer.tsx` → 视口固定 + `<g>` 反向平移 + 掩码覆盖全平面
- `web/src/styles.css` → `.canvas__world`、平移光标、层级调整

## 未来影响

1. 缩放（选项 B）若要做，入口已经清晰：`view` 加 `zoom`，锚点测量改为对世界层做差后除以 zoom，
   react-rnd 传 `scale`；SVG 因为留在视口内，缩放仍只是改 `<g>` 的变换。
2. 小地图/适应内容属于同一族功能，`resetView` 的包围盒计算可直接复用。
3. **portal 教训**（见当日日志）：React portal 会沿 React 树冒泡合成事件，
   任何"用 DOM 包含关系判断事件来源"的手势逻辑都必须改用 `composedPath()`。
