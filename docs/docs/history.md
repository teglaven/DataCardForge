## 1. 一句话

一个工业/科研向的**数据矩阵批处理工作台**，在 71 天里被推翻了四次主要方向：
**Qt/C++ 前端 → 冻结前端先做后端 → 纯 Web/TS → 后端重新持有计算**。
每一次推翻都不是加了新功能，而是**对同一条核心诉求（最坏情况没有墙）的理解变深了**。

## 4. 四个时代（每个都是"越界 → 修正"的结构）

### 4.1 时代一 · Qt/C++ 单体（≤ 2026-08-07）

**形态**：C++/Qt Widgets 桌面应用，`core/` 为数据层，`widgets/` 为界面。
**当时信奉**：后端能算什么决定前端能展示什么 → 先把后端（Eigen 线性代数、逐元素公式）做扎实。

**埋下的坑（最贵的一个）**：
> README 把 **Eigen 列为 "Next priority"**，但 `third_party/eigen` 只是一个**没有 `.gitmodules` 的裸 gitlink**，
> clone 之后必然是空目录；`CMakeLists.txt` 与 `src/` 里**零 Eigen 引用**。
> 即"Eigen 已在后端就绪"**从未成立**。

**为什么当时没发现**：它不影响编译（因为压根没链接），只影响**判断**——
整个 8 月的优先级排序建立在一个不存在的资产上。

### 4.2 时代二 · 冻结前端（2026-08-07 → 10-14）

**决策**：前端选型（ImGui / Web）**暂停**，视图层用 Qt 凑合。
**理由**：避免在"未来可能换掉的技术"上重复投入。

**事后判定为错的前提**（写在该决策的追记里）：
> "矢量导出是**可能**的需求" —— 它其实是**终点需求**。
> 教训：**区分"用户最终要交付什么"和"中间过程需要什么"，前者不能延后决策。**

### 4.3 时代三 · 纯 Web / TypeScript（2026-10-14 → 10-17）

**决策**：前端定为 Web，主实现 `web/`，**算法在 TS 里重写**。
**权重重估**：矢量导出免费（ECharts SVG 原生、ImPlot 明确无导出）、中文 IME 免费、
"WebView 嵌入 ImGui"的复杂度整体消失（浏览器即宿主）。性能顾虑被实测证伪（万行只需 23 个 DOM 行节点）。

**这是全项目最关键的一次副作用**：
> "用 TS 做数学计算"**从未被单独提出**。它藏在 10-14 决策的**"代价"**一节里——
> "`core/` 的算法在 `web/src/core/` 重写为 TypeScript，语义对齐靠测试而非共享二进制"。
> 同一天日志还把口子开着：*"Web 侧要评估 WASM 还是 TS 实现"*。

**随后一天被追认为"基线"**：10-15 兜底原则把 T1 定为浏览器内 TS、角色是"永远可用的兜底层"。
但原则文档自己点破了更早的错误：
> 之前一路用**性能交叉点**口径论证（"TS 够快就不做后端"），是**用户重新锚定核心诉求**后整个口径作废——
> 后端存在的理由不是"更快"，而是**移除天花板**（算法覆盖、内存上限、最坏算力）。

### 4.4 时代四 · 后端持有计算（2026-10-17 → ）

**决策（B 方案，用户拍板）**：数值/统计/矩阵计算全部归服务端；浏览器只做渲染与交互。
用户原话：*"现在直接奔向 B……真有动态需求，日后把公式发给后端解析甚至编译，也不要在前端算。"*

**触发它的是一次实测**（函数卡设计评审暴露分层漏洞）：

| 载荷 | JSON | 编解码 | 一次往返 | 本地 JS 同量计算 |
|---|---|---|---|---|
| 标量 | 22 B | 0.003 ms | **1.27 ms** | — |
| 10×10 | 1.9 KB | 0.039 ms | **1.11 ms** | 0.0099 ms |
| 100×100 | 193 KB | 3.19 ms | **2.32 ms** | 4.68 ms |

> 小矩阵下过界成本 ≈ **固定延迟 × 过界次数**，与字节数无关。
> 一条 10 节点小矩阵链逐边跨进程 ≈ 8.3 ms；整链留在同进程 ≈ 0.075 ms（**约 110 倍**）。
> 结论：**混合分层（这张卡 T1、那张卡 T3）在小矩阵工作流下必然退化成按边付费的最坏情况** →
> 只能"整图待在某一侧"，两个极端里选了**整图进后端**。

**对前代决策的修订**：T1 不再是基线、退出生产计算路径；
`expression.ts` / `stats.ts` / `Smoothing.ts` **冻结为差分测试的参考基准，逐步退役**。

## 5. 四条"螺旋线"（同一个问题被反复遇见）

历史的价值不在日期，而在**哪些问题反复出现**。四条线各绕了两圈以上：

### 线一 · 计算放哪：前端 → 后端 → 前端(TS) → 后端

每一次迁移都换了一套论据：**能力不足**（8月）→ **用户需求权重**（10-14）→ **最坏情况兜底**（10-15）→ **往返延迟经济学**（10-17）。
真正稳定下来的不是"放哪"，而是判据本身：**"操作人员会不会撞墙"**。

### 线二 · 语义一致靠什么保证

`共享二进制`（C++ 直用）→ `测试与断言对齐`（TS 重写，154 用例）→ **跨层共享夹具 + 差分测试**（TS 与 C++ 跑同一套 JSON 夹具）。
第三形态最严格，且被要求**先于引擎落地**（夹具先行）。
2026-10-27 这条线扩到了**卡片层**：`web/tests/fixtures/cards/*.json` 由 TS（端口绑定推导与夹具自洽）
与 C++（真实 `NodeRegistry` 算出的矩阵与结构化错误）双边跑——在此之前，卡片→端口的映射有
**三份互不相同的定义**（前端模型 / 前端 DTO / 后端 PortBinding），而没有任何东西能指出它们不一致。
> 出处：[backend-protocol-v1 §差分测试契约](architecture/backend-protocol-v1.md)、
> [卡片 schema v2 §实施结果](decisions/2026-10-26-card-schema-v2.md)

### 线三 · 仓库形态：一份实现 vs 两份实现

C++/Qt 树曾作"行为参照"保留 → 发现它**成本 215 MB、还让主实现 `web/` 游离在版本控制之外** → 彻底删除。
> 整理出的方法：**先把要留下的东西纳入版本控制，再删要扔掉的东西**——名义上不可逆，实际可逆。

### 线四 · 验证方式：断言 → 真实产物 → 逐像素/几何

`smoke.mjs` 的检查数从 31 → 58 → 61 一路增长，却在 61 项全绿的同时**存在"右键菜单跑到视口外"这种让核心功能完全不可用的缺陷**——
因为测试按选择器点击，从不验证**位置、可达性、视觉正确性**。
> 教训：**端到端测试通过 ≠ 界面能用**；断言数字也不足以验证可视化，**必须真正看图**（因此固定产出截图）。
>
> 2026-10-27 又抓到同一家族的一个变体：函数卡只拉了一个 `count=5000` 的结果窗口，于是 1 万行的
> 源表在卡里只显示前一半——**数字全对、图在撒谎**。差分夹具（判"算得对不对"）一个都抓不到，
> 因为它不是计算错误而是**搬运不全**。对策是给真实后端加一条集成门禁。

## 6. 教训清单（可直接当评审清单用）

### 6.1 关于"不要相信文档说的资产"

1. **"已在就绪"必须可编译可运行才算**。Eigen 的 gitlink 教训：没有 `.gitmodules` 的子模块 = 空目录。
   本次整理复核（2026-10-17）：备份仓库 `repo.git` 中，含 eigen 的路径**仅** `third_party/eigen` 一个 gitlink，`CMakeLists.txt` 与 `src/` 均零引用——**假前提确认成立**。
2. **"可复跑"不等于"在别人机器上能复跑"**；私有 hack 必须固化成仓库内脚本才算回归防线。
3. **"文档写了"不等于"代码有"**：`setEditable` / `setCell()` 在 README 声称可用，实际全仓无调用点。

### 6.2 关于验证

4. **测试顺序会藏 bug**（先滚动后建图，正好掩盖锚点失效）。
5. **自测通过 ≠ 图形正确**（小提琴图画错两次）。
6. **能编译 ≠ 在检查**（`Extract<SeriesOption, {type:'custom'}>` 静默退化为 `any`）。
7. **去掉一个掩盖性 bug 时，必须同时验证依赖数组完整**（"每次渲染都重算"同时是另一 bug 的遮羞布）。

### 6.3 关于静默失败（兜底原则点名要治的）

8. 解析缓存按**文件名**键控 → 今天的曲线顶着昨天的标签。
9. 热力图把"未定义的相关系数"画成 `0` → 语义从"无法定义"变成"不相关"（**主动误导**）。
10. `&&` 写在优先级表里但词法器从不产出 → 多条件筛选静默不可用。
11. 工作区快照只从图表卡重建依赖 → 公式卡依赖重载后**静默丢失**。
12. 显式 X 轴是冻结快照 → 换文件后曲线画在旧文件的自变量上。

> 评审时对任何新路径问三个问题：
> **它在什么情况下会失败？失败时操作人员看得见吗？降级时它显示什么？**

### 6.4 关于决策过程

13. **区分"终点需求"与"中间过程需求"**——矢量导出被误判为"可能需求"，代价是 8 周的前端冻结。
14. **哲学冲突的解决方式是"追问最坏情况"，不是"找性能交叉点"**。
15. **拍板权收束**：全项目 9 个提交的作者均为 `teglaven`，关键决策文档标注"由用户拍板"，
    分工见 README 致谢——**手段用 AI，目的/架构自己定**。

## 7. 现状盘点（2026-10-17）

### 7.1 已确立

| 维度 | 现态 | 出处 |
|---|---|---|
| 前端 | Web，`web/`（React 19 / TS 7 / Vite 8 / ECharts 6 @ SVG） | 10-14 决策 |
| 后端 | **新建 `backend/`**：C++/CMake 服务，矩阵存储 + 依赖图 + Eigen 算子 + 调度 | 10-17 决策 |
| 计算归属 | **全部在服务端**；前端只做渲染布局（坐标轴/虚拟滚动取窗/SVG 位图导出） | 10-17 决策 |
| 传输 | HTTP/1.1 本地服务（默认 `127.0.0.1:37811`），JSON 控制 + 二进制帧（magic `DCM1`）+ 长轮询事件 | 协议 v1 |
| 环境 | g++ 15.2.0 / cmake 4.2.3 / ninja 1.13.2 / **Eigen 3.4.0 已预装**（冒烟编译通过） | 10-17 决策 |
| 错误契约 | 服务端只发 `code + params`，**永不发面向用户的句子**；文案由前端 i18n 渲染 | 协议 v1 |
| 回滚基线 | tag `v1.0.0`（`d077fce`） | commit |

### 7.2 待办（来自 10-17 决策）

- **阶段 0**：跨层共享夹具先行（`web/tests/fixtures/xlayer/`）
- **阶段 1**：`backend/` 骨架 + 协议握手 + Matrix/Node 端点
- **随后**：`expression.ts` 语义移植到 C++（含 `code + params` 错误码表）、Eigen 算子、
  前端 `workspaceStore` 从"持有矩阵"改为"命令 + 订阅客户端"、`VirtualTable` 窗口化数据源
- `stats.ts` / `Smoothing.ts` 的搬迁排在函数卡之后；**自 10-17 起前端不再新增任何数值计算**

### 7.3 已知缺口（明示，非静默）

- 后端不可达 ⇒ 计算全不可用（**单点依赖**，对策：显式横幅 + 重试 + 页面加载即探活）
- 本地固定延迟 ≈ 1.1 ms/往返
- 大结果不能整包下传（10⁷ 行走不了 JSON）⇒ 窗口化 + 二进制帧
- 无鉴权；跨机部署前必须补 token
- PDF 是**位图封装**、**不提供 EPS**（浏览器端无 PostScript 生成路径，属平台约束）
