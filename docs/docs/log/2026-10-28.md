## 今天做了什么

### 一、用户报障两句，实际是两个"看起来像小事"的大洞

用户贴了两张图：

1. 公式卡里输入 `时间_秒 * 2`，界面回一句「无法识别的字符「{char}」(第 0 个字符)」；
2. 空白画布上点「打开数据文件…」，什么都没发生。

两句都当场复现了，根因都不是 UI 层面的：

**第 2 条**：`CardCanvas.onPointerDown` 在"左键按下且没落在 `.card` 上"时立刻
`beginPan()` 并对 canvas 调 `setPointerCapture`。捕获把随后的 `pointerup` 重定向到 canvas，
浏览器于是把 `click` 派发给最近公共祖先——也就是 canvas。按钮自己的 click 永远不触发，
`pickFiles()` 一次都没跑过。拖拽导入与右键菜单走别的路径，所以一直正常，问题因此藏了很久。
浏览器实测：`btn-pointerdown → canvas-gotcapture → canvas-pointerup target=canvas →
canvas-click target=canvas`，而 `element.click()`（绕开指针序列）立刻弹出文件框。

**第 1 条**：三个缺陷叠在一起——

| # | 缺陷 | 后果 |
|---|---|---|
| 1 | 词法器只认 ASCII 标识符 | 中文注解名第 0 字节就 `unexpectedChar` |
| 2 | 带表头列只注册 `Pos.1 名称`/`1 名称`/`名称` 三个键，**唯独没有 `Pos.1`**（`label()` 把位置名和注解拼成一串） | 「`Pos.N` 也可引用」的注释承诺对任何带表头文件都是假的 → **没有任何可用列名** |
| 3 | 节点层只把 `position` 上路，`char`/`name` 留在 C++ | 界面打印字面量 `{char}`，用户拿到一句无法行动的话 |

第 2 条是决定性的：公式卡在**所有带表头的科学数据**上都是死的，不是"不直观"。

### 二、新语法：一列能用它广告出来的任意写法引用

见[决策记录](../decisions/2026-10-28-expression-reference-syntax.md)。要点：

- `Pos.1`（大小写不敏感）、裸注解名、`[地面速度_μm/s]`（方括号内逐字保留）、
  端口限定 `A.pos.1` / `src.时间_秒` / `A.[…]`；全角标点按 ASCII 等价物处理。
- 两套引擎同步改（C++ 生产路径 + TS 差分基准），xlayer 夹具 **71 → 81 例**。
- 错误参数结构化：`char`/`name`/`token`/`min`/`max`/`expected`/`got` 全部上路；位置改为
  码点计数，中英混排时报错位置才与 TS 侧一致。
- 默认表达式也改了：名称用注解（可读），表达式里的引用只在可拼写时用注解，否则退 `Pos.N`。
  否则默认公式就是一次演示失败的示范。

## 教训

- **「click 没反应」先怀疑指针捕获。** `setPointerCapture` 会把 `pointerup` 重定向，
  浏览器随之把 `click` 派发给最近公共祖先——监听器没坏，事件根本没到。
- **一个字段的回退写法也必须能解析。** `Pos.N` 被文档承诺了三个月，对带表头文件却一直是
  死的；夹具只用了 `A`/`B` 这种名字，于是两侧引擎都很"一致地"错了。
- **CSS 塌陷只在真实数据下显形。** 空结果时三区布局看着正常，出结果就少一行；
  布局问题只能靠真实浏览器 + 真数据，jsdom 看不见。
- 指针捕获这条是**没有任何端到端覆盖**才长期存活的：拖拽路径有覆盖，文件框路径没有。
  现在两条都有。

## 附：一份独立复审换回来的东西

实现完交给一个**全新上下文**的子代理复审（它不看我的推理，只看仓库与浏览器），
换回五条真问题——其中一条是我自己"讲过的规则"错了：

1. **数字开头的注解仍然拼不出来**：默认表达式的判据只拦"纯数字"，而词法器在**任何**
   前导数字处就开数字字面量。`2号测点` 这类真实台站命名 → 默认表达式 `2号测点 * 2` →
   「表达式结束后多出「号测点」」。判据改为 `/^[\d.]/`。（我说"判据与词法器同源"，
   实际不同源——这就是复审最值钱的地方：它只信代码。）
2. **无焦点点「可用列」芯片会追加到末尾**：`时间_秒 * 2Pos.2` → 红卡片。芯片本身是为了
   教 `Pos.N`，却先演示了一次失败。无焦点时改为整段替换。
3. **建议挂错了错误码**：用户原样输入 `地面速度_μm/s * 2` 得到的是 `unknownColumn`
   （在 `/` 处截断），而"用 Pos.N 或 [列名]"的提示挂在 `unexpectedChar` 下——永远不会被看到。
   现在提示同时挂在三种错误旁（卡片里直接显示一行灰字），并把"数字开头"补进列引用表；
   带括号的列名（`温度（℃）`）裸写会被读成函数调用，也归进这条提示。
4. **防漂移测试的 oracle 其实只覆盖 cell 模式**：C++ 的 `functions()` 多 6 个矩阵专用函数。
   测试里写清这条边界，说明书里也注明它们为何不列出。
5. **`/api/hello` 的 build id 是配置时的快照**：二进制已是最新却报旧提交——
   "新引擎部署上了吗"被一个过期字符串答错了一次（我自己就被它误导过）。

复审判定通过的（抽样）：四条取文件路径、平移/选中无回归、真浏览器里 14 种表达式写法、
悬停 0/300 ms → 1/1200 ms 且在指针位置、帮助四处入口、工作区往返、zw/en 251 键相等。
