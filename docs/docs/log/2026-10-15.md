### 2. 五个缺陷修复

#### A · 横向滚动会让连线脱离列头
README 承诺"列滚出视口→线吸附到边缘"，但 `invalidateLayout()` 在 `VirtualTable` 里**一次都没调用过**：`setTableMetrics` 只在 offsets/widths 变化时跑，行是绝对定位所以也不触发 resize。结果 `headerAnchor()` 读到的 `scrollLeft` 停留在上次拖拽时刻。

修法只有一行：`handleScroll` 里补 `invalidateLayout()`。

**值得记的方法论**：这个 bug 冒烟测试跑了 58 项全绿却看不见——因为测试是"先滚动、后建图"，锚点在建图时被重新计算了一次，正好掩盖问题。**测试顺序会藏 bug**。现在加了专门的检查（滚动后比较 path 的 `d` 属性）。

#### B · 按文件名复用解析结果 = 静默返回旧数据
`matrixIdByFile.get(entry.name)` 命中即复用。传感器场景下 `export.csv` 每天被覆盖，于是今天的文件画出昨天的曲线。而且 `parseFiles` 的去重集合是每个 batch 新建的，跨批次根本不受保护。更糟的是旧测试把这种行为**写成了预期语义**。

改成内容寻址：缓存键换成 `size:lastModified`，`LoadedFile` 带上 `identity`；无 identity 的条目（程序建表 / 快照恢复）永不共享。恢复工作区时故意把缓存清空——磁盘字节已经不在了，重新拖入必须重新解析而不是悄悄指向还原的数据。

同时把那条固化错误的测试反转，并补了三条：同名不同内容不复用、同字节复用、无 identity 不共享。

#### D · `toSnapshot` 名称反查丢名字
`[...matrixIdByFile.entries()].find(([, mid]) => mid === id)?.[0] ?? '#id'`——两张卡片持有同名文件时共享一个 matrixId，反查只能命中一条，另一张的名字退化成 `#3`，还原后又用 `#3` 污染缓存。改为**从真正引用它的卡片去取名**，缓存不再参与命名。

#### E · 依赖图无环检测、边会重复注册
`addDependency` 用数组 push，同一关系注册两次就会让 `getDependents` 返回两个相同 id（刷新链路重复执行）。且完全没有环检测——现在 chart→matrix 单向还成不了环，但函数卡一旦落地就能。

改用 `Map<number, Set<number>>` 天然去重；加边前做一次 BFS，若 `dependsOn` 已传递依赖 `dependent` 则拒绝，并返回**首尾同节点的环路径**（`[4,3,2,1,4]`）供 UI 直接展示。`loadSnapshot` 也会跳过保存文件里非法的边并提示。

踩坑记录：第一版把 BFS 方向搞反了（顺着 dependents 找而非顺着 dependsOn 找），三次迭代才对齐——**方向性错误靠读代码很难发现，靠测试立刻暴露**。

#### F · 解析阻塞主线程
10 000×10 的 TXT 解码 + 逐格数字语法校验是纯 CPU 活，XLSX 更久，期间界面完全冻结。

新增 `parse.worker.ts` + `parseWorker.ts`：Vite 原生生成的 module worker，回传结构化克隆友好的 `ColumnPayload[]`。两个设计约束：
- **回退优先**：没有 Worker 的环境（vitest/node、禁用 worker 的 webview）自动走原来的同步路径，优化绝不能变成打开文件的前置条件；
- **类型单独成模块**：worker 入口在 import 时就装 `onmessage`（访问顶层 `self`），客户端只需类型，于是抽出 `parseTypes.ts`，否则 node 环境直接 `self is not defined` 崩掉整个 suite。

产物验证：worker chunk 488 KB（xlsx 解析器随之移出首屏），首屏仍 104 KB gz 未退化；浏览器里确认 worker 真的起来了（`page.on('worker')` 抓到 `parse.worker-*.js`），不是静默回退。

### 3. 暂缓（按用户决定）

**C · 图表复制 `raw: column.data.slice()`** —— 每个 ChartSource 各存一份全量列数据，10k×10 挂满图表会是数十 MB 级 `number[]`；全项目零处使用 `Float64Array`。

用户判断：**每个节点本就是独立对象，这是设计理念的一部分**，不属于缺陷。故不动。留此记录，若将来大表内存成为实际瓶颈再议。

## 第二轮：前端 UI 与图表逻辑缺陷审查（对抗式验证）

针对「UI 显示 + 各种图的操作逻辑」做了一轮系统审查：静态通读全部前端源码，再用 headless Chromium 在**生产构建**上做交互探测、逐像素取色、下载产物校验，并另开一条并行的样式交叉审查（对比度计算、层叠上下文推导、最小尺寸算术）。完整报告见 [`docs/audits/2026-10-15-ui-chart-defect-audit.md`](../audits/2026-10-15-ui-chart-defect-audit.md)。

### 抓到的两类"只有跑起来才会暴露"的问题

1. **react-rnd 的 `transform` 会劫持 `position: fixed`**。卡片用 `transform: translate()` 定位，于是卡片成为其后代中 `position: fixed` 元素的包含块，再加上 `.card { overflow: hidden }`，列头右键菜单被整体平移了卡片自身的偏移量。卡片在 (800,454) 时菜单渲染到 **(1965,981)** —— 视口 1440×900，10/10 个菜单项全部不可见。由于"右键列头 → 选图型"是创建图表的**唯一**入口，这等于把图表功能废掉了；而 `smoke.mjs` 之所以一直通过，是因为它按选择器点击，从不检查位置。
   → 修复：新增 `components/Popup.tsx`，用 portal 渲染到 `body`，保留视口定位并做边界钳制与向上翻转。

2. **一个"看起来正确"的性能修复暴露了潜伏的生命周期缺陷**。`useTranslator()` 原本每次渲染都返回新的 `t`，导致 `strings`/`option` 的 `useMemo` 每次渲染都失效，于是每次 store 变化都会对所有图表卡执行 `setOption(..., { notMerge: true })`（实测：改图表 A 的平滑模式，B、C 也各被重建一次）。按 locale 缓存 translator 后引用稳定了——**但图表初次创建后变成空白**：`setOption` 的 effect 依赖 `[option]`，而 ECharts 实例是懒加载后异步创建的，`option` 在实例出现时并不会变。此前那个不稳定的 `t` 恰好掩盖了这个缺失的依赖。
   → 修复：把实例放进 state，effect 依赖 `[chart, option]`。

   教训：**"每次渲染都重算"是个 bug，但它同时是一张掩盖别处 bug 的网**。去掉它时必须同时验证依赖数组真正完整。

3. **我自己的回归**：把 `event.currentTarget.getBoundingClientRect()` 写进了 `setPanel(current => ...)` 的更新函数里。React 在事件处理函数返回后会把 `currentTarget` 置空 → `Cannot read properties of null` → 没有错误边界，整个应用白屏。端到端测试与并行的浏览器审查同时抓到。

### 几个"科学正确性"层面的修复

- **热力图把未定义的相关系数画成 0**。`pearson()` 对常数列返回 `NaN`（并有单元测试断言），但绘图时被 `Number.isFinite(x) ? x : 0` 改写成 0 —— 在 -1..1 的双向色标上落于白色，语义从"无法定义"变成"不相关"。这是主动误导，不只是显示问题。→ 保留 `NaN`（ECharts 留空），标签显示 `—`。
- **显式 X 轴是冻结快照**。`refreshDependentCharts` 只重指 `sources`，完全没管 `xAxisSource`（它存的是 `col.data.slice()` 的副本）。切换文件后曲线被画在**旧文件的自变量**上，且毫无提示。实测切换前后 X 值完全相同而 Y 已更新。→ 一并重指；列消失则回落行号，保证下拉框标签与图表一致。
- **公式卡是陈旧的**。它通过依赖图登记为依赖方，但 `refreshDependentCharts` 只处理 `isChartCard`，所以源表换文件后公式结果仍是旧文件的。→ 依赖方中一并重算。
- **"可编辑单元格"在 UI 上不可达**：`setEditable` 全仓无调用者，`addMatrixCard` 一律 `readOnly: true`，于是 `editCell` 只在单元测试里被调用过。→ 矩阵卡文件行加了锁定/编辑按钮，编辑改用与显示侧同一套严格数值文法（`Number('')` 是 0、`Number('0x10')` 是 16、`Infinity` 会被写进矩阵）。

### 有价值的量化结论

- **最小尺寸算术**：图表卡在 280×180 下，正文只有 148px，而工具栏 31 + 页脚 65（换行时 117）+ 绘图区 `min-block-size: 80px` = 176+，平滑控件整行落在卡片外 80px 且无法触达。`min-block-size` 还悄悄压掉了同一规则里的 `min-height: 0`。→ 绘图区下限降到 48，卡片最小高度提到 240。
- **弹层裁剪**：280px 宽时坐标轴面板被最长的文件名撑到 540px；最小高度下类型下拉只剩 5/9 项可达。→ portal + `max-width` 后 9/9 可达。
- **对比度**：深色模式下 `#fff` on `--accent` = 2.90:1、`--danger` 未在深色块重声明 = 2.71:1、闲置连线灰 2.27:1、状态栏提示 2.76:1、空状态提示 4.20:1。→ 引入 `--on-accent`/`--on-danger`、加深连线灰、状态栏提示在窄屏隐藏。
- **`text-overflow` 在 flex 容器上不生效**：文本是匿名 flex 项，永远收缩不到 min-content 以下，省略号因此从不渲染（列头还被 `justify-content: center` 两侧同时切）。→ 标签改为独立 `<span>` 盒子。

### 一处可见行为变更

连线图层从 `z-index: 900`（压在所有卡片之上）降到卡片之下，并用 SVG 遮罩按卡片矩形挖洞 —— 兑现 `ConnectionLayer` 自己声明的"连线是背景可视化"。代价是画在 SVG 里的"源列高亮框"会被卡片遮住，因此把该标记改到 **DOM** 上（`.vtable__colhead--source`，选中图表时其源列列头高亮）。逐像素复核：卡片内部连线像素 **0**。

### 教训

**端到端测试通过 ≠ 界面能用**。`smoke.mjs` 的 61 项检查全绿，同时却存在"右键菜单跑到视口外"这种让核心功能完全不可用的缺陷——因为它按选择器点击，从不验证**位置**、**可达性**和**视觉正确性**。下一轮应给冒烟测试补三类断言：① 关键操作的落点必须在视口内；② 关键控件必须在自身容器内（不被裁剪）；③ 用逐像素/几何比对验证"该看见的看见了、不该看见的没看见"。
