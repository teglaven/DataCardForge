## 今天做了什么

### 一晚把函数卡从「规格」做到「能跑」

上一轮定稿了[卡片数据结构 v2](../decisions/2026-10-26-card-schema-v2.md)与[端口语义规格 v1](../architecture/port-semantics-v1.md)，
但没有一行实现。这一轮按依赖顺序把它落成六个可独立回滚的提交，每步都过闸
（vitest / ctest / 三 systemd 单元）。

顺带发现并修掉一个**真实缺陷**：`PATCH /api/matrices/{id}` 只发事件、从不调用
`onMatrixChanged`，于是改一个单元格后函数卡继续显示改动前的数字——数字错了，灯还是绿的。
实测：源表 `A[0]` 由 1 改 10 后，依赖节点输出仍停在 `[2,4,6]`（应为 `[20,4,6]`）。

### 顺序为什么是后端先行

原计划先做前端 schema，但前端的 v2（单节点 K 输出）需要后端先能表达 K 输出与签名。
因此实际顺序是 **后端节点 v2 → 签名注册表 → 前端 schema 迁移 → UI → 交互**。
协议全程保持增量（`portId`/`sourceOutputIndex`/`resultMatrixIds`/`signatureId` 都是新增字段），
所以任一提交单独部署都不会让另一端失效。

### 三条被实现推翻或修正的设想

1. **列头指纹没做**（用户裁决）。线性代数链路列变动太常见，指纹误报率与复杂度不成比例。
   换成**显式列数契约**：命名输出列即锁宽度，漂移由后端断流，自编辑走「扩展/解除」一步确认。
2. **输出列名不另存一份**。原计划 `outputs[].columnNames` 与表达式名并存，等于给同一能力
   开两个入口；最终列名只属于签名参数，输出区顶端只是它的另一个编辑面。
3. **「行数变化要确认」被放宽**。表达式按列名取值，行数不是映射；行数变化只陈述不阻塞，
   只有列集合变化才需要「仍然应用」。

### 本轮最贵的一课：**先看「谁会消费这个数字」，再谈形状**

`fetchFullResult` 之前的 `count=5000` 是协议默认值，不是缺陷——缺陷是**前端把默认值当成了
全部**。这类 bug 的共同点是：数字来自后端（所以看起来可信），被截断发生在客户端（所以后端
日志干净），而 UI 不会报错。`xlayer` 的 46 个夹具一个都抓不到它，因为夹具判的是「算得对
不对」，不是「搬得全不全」。→ 现在有一条集成门禁专门打真实后端。

### 第二轮：把「输入输出连通」真正做完

第一轮结束时函数卡的**输入侧**通了（显式矩阵、端口、重指向），但**输出侧**只到「表格」为止：
审计里那条「公式列无法绘图」仍然成立。这一轮补齐出口，并顺手修掉三个伴随问题。

1. **结果可流动**。函数卡的输出本来就是普通矩阵（`displayMatrixId`），后端也早把结果矩阵
   当中间边，缺的只是入口。现在右键结果列头 → 建图，或「新建公式卡…」链到下一张卡：
   - `addChartCard` / `addFormulaCard` 改为接受「能拥有矩阵的卡」（数据卡或函数卡）；
   - 关卡保护从「矩阵卡专属」改为「任何被依赖的卡」；
   - 图表源统一经 `ownerCardOfMatrix` 解析，一份规则；
   - 函数卡拿到新结果后刷新读它的图表（此前只有数据卡切文件会刷新）。
2. **能力协商**。协议号仍是 1（v2 字段全增量），但一个不认 `signatureId` 的旧后端会忽略它
   并求值空 `formula`——造出「活着但什么都没算」的节点。新增 `signature.v1` / `card.v2` 能力，
   前端把 `signature.v1` 列为必需，缺失即走既有「后端版本不兼容」横幅。
3. **事件轮询空转**（真 bug）。`/events` 返回非数组时，循环跳过 250ms 退避直接空转：
   一个回答错形状的测试桩把它放大成 12 秒 4600 次请求并 OOM。现在把「非数组」与「空数组」
   同等对待。
4. **定义版本守卫**。求值无锁带来的新窗口：算到一半定义被改，旧结果仍以 Done 提交。
   `definitionVersion` 在 update/updateParams 时自增，提交前比对，不一致则回落 Dirty。

### 一组实测数字（本机，10 万行 × 2 表达式的函数卡）

| 环节 | 耗时 |
|---|---|
| 矩阵注册（JSON，1 列 10 万行） | 77 ms |
| 建节点 + 后端求值（2 个表达式） | 5 ms |
| 前端翻页取全结果（20 个窗口） | 70 ms |

结论：10⁵ 量级的函数卡是**交互级**的，不需要为它做惰性取窗；20 万行的缓存上限只是防病态。
