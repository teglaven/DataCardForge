### 2. 函数卡设计评审 → 暴露分层的"图的账"

评审意见聚焦三点：A/a 大小写语义要冗余显示（不能只靠颜色）、指示灯需要第四态
"已修改待计算"、以及最重要的——**兜底原则的三层表只算了单次操作的账，没算数据流图的账**。

实测（localhost HTTP+JSON，300 次中位数）把问题钉死：一次过界 ≈ **1.1–1.3 ms 固定延迟**，
与载荷大小基本无关；10×10 矩阵本地 JS 计算只要 0.0099 ms。**一条 10 节点小矩阵链逐边跨进程
≈ 8.3 ms，整链同进程 ≈ 0.075 ms（约 110 倍）**。混合分层（这张卡 T1、那张卡 T3）在小矩阵
工作流下必然退化成按边付费的最坏情况。基准脚本 `/tmp/bench-crossing.mjs`（待收编进 `web/scripts/`）。

### 4. 环境核实（两次结论相反，以实测为准）

上一轮探测说 g++/cmake/ninja/Eigen "NOT FOUND"——**错的**。本轮直接跑二进制验证：
g++ 15.2.0（编译运行通过）、cmake 4.2.3、ninja 1.13.2、Eigen 3.4.0（det/LU 逆冒烟通过）、
gdb 17.1、ccache 4.12.3 **全部预装**。沙箱内 `sudo` 受 `no new privileges` 限制，但无需安装任何东西。
教训：工具可用性要用"能否执行真实工作负载"判定，`apt-cache policy` 的前端包名会误导。

旧备份 `.pre-qt-removal-backup/repo.git` 里的 `src/core/` 确认**不含线性代数**
（third_party 只有 OpenXLSX/QCustomPlot，CMake 只找 Qt6）——数学库从零写。

### 5. 阶段 0 落地：跨层夹具先行

- `web/tests/fixtures/xlayer/expression.v1.json`：38 个用例（算术/优先级/聚合广播/
  MOV/EMA/IF/NaN 传播/非有限哨兵编码/列名解析/错误码+位置），JSON 无法携带 NaN/Infinity，
  用字符串哨位编码，runner 负责复活。
- `web/tests/xlayerFixtures.test.ts`：TS 参考实现侧 runner。**夹具第一轮就抓到两处手算
  期望值错误**（zscore 的样本 STD、EXP(LN(2)) 项），修正后 38/38 绿——这正是"夹具先行"的价值：
  C++ 引擎将对着同一份 JSON 验收，而不是对着移植者的记忆。
