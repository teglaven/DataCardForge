# 决策：后端持有数据与计算，浏览器退化为纯交互界面（B 方案）

- **日期**：2026-10-17
- **状态**：✅ 已确立（本会话由用户拍板："现在直接奔向B，浏览器就是纯粹的交互界面，真有动态需求日后把公式发给后端解析甚至编译也不要在前端算"）
- **标签**：`#架构 #后端 #计算分层 #函数卡`
- **基线**：本决策实施前的回滚点为 tag `v1.0.0`（提交 `d077fce`，"画图功能完成"）。

## 核心表述

> **数值 / 统计 / 矩阵计算全部在服务端；浏览器只做渲染与交互。**
> 前端唯一保留的"计算"是渲染布局本身：坐标轴布局、虚拟滚动取窗、SVG/位图导出。
> 公式的解析、编译、求值都属于计算，一律在后端；前端只搬运公式文本。

## 背景

- [兜底原则](2026-10-15-max-headroom-principle.md) 确立了三层：T1 浏览器 TS（基线）、
  T2 WASM、T3 原生后端。其中 T1 承担"永远可用"的基线角色。
- 函数卡设计评审中暴露出该分层**没有覆盖数据流图的账**：函数卡是"多卡连线、
  频繁卡间信号触发"的负载。实测（本机 localhost HTTP+JSON，300 次中位数）：
  | 载荷 | JSON 大小 | 编解码 | 一次往返 | 本地 JS 同量计算 |
  |---|---|---|---|---|
  | 标量 | 22 B | 0.003 ms | **1.27 ms** | — |
  | 10×10 | 1.9 KB | 0.039 ms | **1.11 ms** | 0.0099 ms |
  | 100×100 | 193 KB | 3.19 ms | **2.32 ms** | 4.68 ms |

  小矩阵下过界成本 ≈ **固定延迟 × 过界次数**，与字节数无关。一条 10 节点的
  小矩阵链若逐边跨进程：~8.3 ms；整条链留在同一进程内存里：~0.075 ms（约 110 倍）。
  且 10×10 级别 Eigen 对 JS 并无算力优势——**混合分层（这张卡 T1、那张卡 T3）
  在小矩阵工作流下必然退化成按边付费的最坏情况**。
- 出路只有"一个子图整体待在某一侧"。两个极端：A = 整图留浏览器（T1 基线不变，
  T3 仅作逃生舱）；B = 整图进后端（卡间信号变成进程内交接，µs 级）。
- 2026-10-17 用户拍板选 **B**，并要求把"日后公式连解析都发后端"也纳入边界规则。

## 选项

| 选项 | 内容 | 判定 |
|---|---|---|
| A. 整图浏览器 + T3 逃生舱 | 小矩阵默认全在 T1；仅 T1 做不到的节点跨边界 | 被否：仍是双实现，语义一致靠差分测试长期维持 |
| **B. 整图后端** | 数据、依赖图、解析、计算、调度全在服务端；浏览器纯视图 | ✅ **采纳** |
| C. 按卡混合分层 | 每张卡独立选层 | 被否：实测 110 倍的按边付费场景，正是本次推翻的对象 |

## 结论细则

1. **权威归属**：服务端持有矩阵数据、文件解析结果、依赖图（含每输入端口的边）、
   计算节点定义（输入绑定 + 公式文本）、求值结果、节点状态机。
   浏览器持有卡片几何/层叠、端口与连线渲染、输入捕获、i18n、对话框、指示灯显示。
   两侧用同一套 node id 对齐（服务端知道"计算节点"，浏览器知道"卡片"）。
2. **缓存语义**：浏览器的矩阵副本降级为**按 revision 键控的只读显示缓存**；
   一切变更都是发给服务端的命令。这落实了兜底原则"严格分离"一行里预告的
   "后端持不可变缓存、编辑永远产出新卡"。
3. **传输**：HTTP（JSON 控制消息 + 二进制矩阵帧 + 文件上传），带长轮询/SSE 的
   状态推送。版本与能力握手先行；WebSocket 升级留待需要更低推送延迟时再做，
   不改变消息语义。（协议规范见 [backend-protocol-v1](../architecture/backend-protocol-v1.md)。）
4. **错误契约**：服务端只发结构化错误码 + 参数（沿用 `expression.ts` 的
   `code + params` 模式），**面向用户的文案由前端 i18n 渲染**。服务端永不发送文案。
5. **对兜底原则的修订**（[2026-10-15-max-headroom-principle](2026-10-15-max-headroom-principle.md) 的分层表就此改写）：
   - ~~T1 浏览器 TS = 基线~~ → **后端 = 基线**；T1 退出生产计算路径，
     其现有实现（`expression.ts`/`stats.ts`/`Smoothing.ts`）**转为差分测试的参考基准**，
     逐步退役，不再是"永远可用的兜底层"。
   - 契约 1"降级必须可见"具体化为：**后端不可达 ⇒ 显式横幅 + 重试，绝不空白**。
     这是本决策接受的单点依赖，属于"已知缺口被明确记录"，不是第三种静默状态。
   - 契约 2"层间语义一致"继续成立且更简单：生产只剩一层，一致性由
     **跨层共享夹具**（先于引擎落地）向新引擎迁移时校验。
   - 契约 3"最坏情况有界且可感知"不变：长任务必须有进度与取消。
6. **图表统计**：`stats.ts`/`Smoothing.ts` 属"数值计算"，最终也要搬到后端。
   排在函数卡之后单独阶段执行；**自本决策起前端不再新增任何数值计算**。

## 接受的对价（明示，非静默）

| 代价 | 表现 | 对策 |
|---|---|---|
| 单点依赖 | 后端不可达 = 计算全不可用 | 显式横幅 + 重试；页面打开即握手探活 |
| 每次数据交互变往返 | 本机 ~1.1 ms 固定延迟；远程更高 | 异步 UI（乐观/骨架/取消）+ 延迟预算 |
| 编辑分叉风险 | 缓存与权威可能不一致 | revision 键控 + 禁止本地变更 |
| 开发/CI 复杂度 | `npm run dev` 不再够 | 一键双端脚本；CI 装 g++/cmake/ninja/eigen |
| 大结果不能整包下传 | 10⁷ 行走不了 JSON | 窗口化读取 + 二进制帧 |

## 环境事实（2026-10-17 核实）

- Ubuntu 26.04；g++ 15.2.0、cmake 4.2.3、ninja 1.13.2、Eigen 3.4.0（`/usr/include/eigen3`）、
  gdb 17.1、ccache 4.12.3 **已全部预装**，Eigen 冒烟编译通过（det/LU 逆正确）。
  无需 sudo/apt（沙箱内 `no new privileges`，也用不上）。
- `.pre-qt-removal-backup/repo.git` 的旧 `src/core/`（MatrixData/DependencyGraph/
  FileLoader/Smoothing，Qt-free）**不含任何线性代数**（third_party 只有 OpenXLSX/QCustomPlot，
  CMake 只找 Qt6）——数学库从零写，旧 core 只提供数据结构形状参考。

## 未来影响

1. 函数卡（FunctionCard）的全部计算语义落在后端；前端只做三区 UI + 端口锚点 + 指示灯。
2. README「三层」表述需随本决策更新（短期目标一节）。
