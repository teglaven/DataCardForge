## 今天做了什么

### 阶段 3：切换计算权威（公式卡数值计算从浏览器迁到后端）

落实 [B 方案](../decisions/2026-10-17-backend-owns-compute.md)的裁定——"公式的解析、编译、求值都属于计算，
一律在后端；前端只搬运公式文本"。此前文件加载矩阵已有 fire-and-forget 注册通路，但
FormulaCard 仍在本地用 `evaluateExpression` 算结果、用前端 `compile()` 做语法校验。今天把这条
生产路径整体切到后端节点系统。

#### 1. 多公式列 ↔ 节点的映射：**每个公式列一个节点**

协议规定一节点一 `formula`，而前端一张公式卡是"多公式列"模型。冲突按预定的优先方案解决：
每个公式列注册一个独立 compute node，卡片持有 `nodes: Array<NodeStatus | null>`（与 `formulas`
下标对齐）。于是编辑某列 → `PATCH /api/nodes/{id}`，删除某列或关卡 → `DELETE /api/nodes/{id}`
并释放其结果矩阵。

端口绑定粒度也做了收敛：不再把一个端口绑整张源表，而是**为公式实际引用的每一列各建一个
matrix-mode 端口**，绑到源矩阵的服务端 id。识别引用只做文本级大小写不敏感匹配（非计算），
避免把无关列灌进节点。

#### 2. 结果显示：事件驱动 + window 拉取，写入按 revision 语义的只读显示缓存

新增单条长轮询订阅（`GET /api/events?since=`，App 挂载时武装、重连后重武装）。节点 `done`
事件到达后，经**协议内既有**的 `GET /api/matrices/{resultMatrixId}/window`（DCM1 二进制帧）拉结果，
解码成 `MatrixData` 写入该卡的显示缓存；每列先落自己的槽位再合并成整表，互不覆盖。
没有扩协议去用未文档化的 `/result` 端点。

四态指示灯数据源改为 `nodeState`：dirty/computing/done/error → 灰/黄/绿/红（CSS `.node-light--*`，
computing 带脉冲动画并对色盲友好）。error 事件用 `code`+`params` 走 i18n key `formula.error.<code>`
渲染；未知 code 显示兜底句 `formula.error.unknown` + 原始码，**绝不静默**。

#### 3. 后端不可达：显式横幅，不回退本地计算

`evaluateExpression` 在生产路径的 import 彻底消失：workspaceStore 删掉 `computeFormulaResult`
及其全部调用，FormulaCard 删掉前端 `compile()` 校验。offline 时节点不注册、显示缓存保持空、
横幅出现——契约 1"降级必须可见"就此具体化。`core/expression.ts` 本体保留（xlayer 差分基准），
顶部注释标注"已退出生产路径，仅作 xlayer 差分基准"。

#### 4. 图表联动继续工作

`refreshDependentCharts` 不再本地重算公式结果；文件切换时改为把该卡各节点重新 PATCH 绑定到新
激活矩阵的服务端 id，结果经事件回流。图表吃的仍是"后端结果矩阵的显示缓存"，数据结构不变，无感。

## 追加：差分 fuzz 门禁，以及它抓到的 6 类真实分歧

上面记的是阶段 3 切换；这一段记同日稍后把 2026-10-18 审计时的临时侦察品
收编为**可复跑的差分 fuzz**（`DC_RUN_FUZZ=1 ctest --test-dir backend/build -R diff_fuzz`）。

### 形态

- `web/scripts/diff_fuzz.mjs`：种子化随机表达式生成器 + TS 权威侧（直接 `import`
  `web/src/core/expression.ts` **本体**，不用旧 bundle 快照）+ C++ 侧
  （`backend/tests/diff_run.cpp`）对拍；既比数值，也比结构化错误
  （`code`/`params`/`position`）。
- `backend/tests/fuzz_gate.py`：ctest 门控，沿用压测的惯例（默认退出 101 → Skipped，
  CI 不变慢）；默认 2000 例/种子，分歧打印最小复现（表达式 + 列数据 + 两侧结果）。

### 抓到的分歧（手写夹具从未覆盖）

| # | 表达式 | TS（参考） | C++（修复前） | 根因 |
|---|---|---|---|---|
| 1 | `SIGN(A)`，A=NaN | NaN | 0 | C++ 用 `(a0>0)-(a0<0)`，NaN 两侧比较皆假 |
| 2 | `MIN(EXP(8.96), LN(B))`，B<0 | NaN | 7785.36 | `std::min` 在 NaN 作**第二**操作数时不传播 |
| 3 | `ROUND(-1.5)` | -1 | -2 | `Math.round` 半值向 +∞，`std::round` 向远离零 |
| 4 | `ROUND(6.66, 6.62)` | 6.6600000146 | 6.66 | C++ 把小数指数 `static_cast<int>` 截断 |
| 5 | `MOV(A, POW(4*B,B))`，B=∞ | 全序列均值 | 原样返回（不平滑） | `llround(∞)` 是 **UB**（x86 得 LLONG_MIN）→ 静默退化 |
| 6 | `POW(1, NaN)`、`POW(-1, ∞)` | NaN | 1 | **ECMAScript 与 C99 规范本身就不同**（C99 规定 `pow(+1,y)=1`，y 为 NaN 也是 1） |

6 类全部按"TS 是参考实现"修复：新增四个忠实语义辅助函数
（`jsRound` / `jsMin` / `jsMax` / `jsPow`），并把 8 条固化为跨层夹具（38 → **46** 例），
两端同过。第 5 条顺带消除了一个真 UB——这与 10-18 审计抓到的 `std::stoul` 属同一族：
**在 detached 线程/热路径上调用对非有限输入未定义的函数**。

> 与教训 §6.1-4 互为镜像：**手写夹具只覆盖作者想到的语义**。这 6 类里第 3、6 条尤其典型——
> 实现"看起来完全正确"，差异藏在语言规范的细节里。

### 处置而非掩盖

fuzz 还报过一类**不是**分歧的东西：`fmod(17.55^17.55, 2.09)`——`pow` 的最后几个 ULP
差异被 `fmod` 放大成任意值。这是浮点敏感性，不是语义差异。处置是**约束生成器**
（`%` 的左操作数改从"无超越函数"子文法生成；`+ - * /` 是 IEEE 精确舍入、两端逐位相同），
**而不是放宽比较器**——后者正是本项目最反对的"用断言掩盖失败"。
验证：**20 个种子 × 2000 例（共 4 万差分用例）全绿**。

### 仍待商榷（未擅自决定）

退化窗口的语义：`MOV(A, 0/0)` 目前两端一致地输出**全 NaN**，`MOV(A, 1/0)` 输出全序列均值。
忠实于 TS 参考优先，但按"降级必须可见"的原则，非有限/非整数窗口是否应该改为**结构化错误**
（而不是静默产出 NaN 序列）值得单独拍板。

## 追加：画布改为无边界平面（无限视图）

用户诉求："根本装不下复杂的工作流"。查下来不是"空间不够"，而是**实现主动把卡片夹在一屏内**：
`placeWithinCanvas()` 把新卡夹回视口、`Rnd bounds="parent"` 把拖拽也限制在视口大小的父容器里。
决策与取舍见 [画布改为无边界平面](../decisions/2026-10-21-infinite-canvas.md)。

落地形态：`.canvas`（视口，裁剪）+ `.canvas__world`（平面，带平移变换）两层；
平面尺寸由卡片推导（拖得越远长得越大）；锚点改为对世界层做差，**平移在几何里自动抵消**，
`cardMetrics` 不需要知道平移存在。平移手势：滚轮/触控板、中键拖、空格+左键拖、空白处左键拖
（>4px 才算拖）；卡片内的滚轮照旧归卡片（表格滚动、图表缩放）。

### 探针抓到的真缺陷：React portal 让"空白画布"判定说谎

单元测试 269 项全绿、typecheck 干净——**但右键菜单建图表已经坏了**：
点"Line"没有任何反应，无报错、无 toast、菜单不关。

浏览器探针把事件轨迹打出来才看清：

```
pointerdown: context-menu__item
mousedown:   context-menu__item
mouseup:     canvas      ← 指针被画布抢走
click:       canvas      ← 菜单项的 onClick 从未触发
```

根因：**React portal 沿 React 树冒泡合成事件**。右键菜单 portal 到 `<body>`，
DOM 上不在 `.card` 里，于是被我的"空白画布"判定命中 → 画布 `setPointerCapture` 夺走指针 →
菜单项的 click 永远不触发。修法是改用 `event.nativeEvent.composedPath()` 判断事件是否真的
发生在画布上。

> 教训（补进 §6.2 验证族）：**"用 DOM 包含关系判断事件来源"在 portal 面前是错的**；
> 而且**单测全绿 + typecheck 干净 ≠ 交互可用**——这类缺陷只有真的点一下才会暴露。

### 验证

- 前端 **280 项**单测（新增 `InfiniteCanvas.dom.test.tsx` 11 项：坐标系、摆放、
  滚轮/中键/点击手势、卡片滚轮归属）
- 仓库自带冒烟 **61 项全过**（含 9 种图型、导出、i18n、无运行时错误）

  旧代码会在这里夹住）；平移后两张卡同屏、红线精确落在 Pos.2 列头（蓝色高亮）；
  卡片上的滚轮不平移画布；视图 → 回到卡片 正确重新取景。

## 追加：整体缩放（滚轮放大缩小整个工作台）

用户：“鼠标滚轮能改为整体缩放吗……放大缩小整个工作台，连通字体图像窗口等等”。
决策与细则见 [画布改为无边界平面](../decisions/2026-10-21-infinite-canvas.md)文末“追加：整体缩放”一节。

实现：世界层 `translate(-view.x,-view.y) scale(zoom)`（`transform-origin: 0 0`），
卡片、表格文字、ECharts 图表、工具栏、连线一起缩放；`cardMetrics` 增加 `setCanvasZoom`，
所有屏幕测量的差值除以 zoom 回到平面单位；react-rnd 传 `scale`；滚轮＝缩放
（卡片内未按 Ctrl 时仍归卡片：表格滚动、图表 dataZoom），按住 Ctrl/⌘ 在卡片上也能缩放
——触控板捏合本来就发 ctrl+wheel，捏合天然可用；围绕光标缩放；范围 10%–300%；
网格按 2 的幂自适应步长（屏幕间距保持 8–44px）；视图 → 回到卡片 改为“适应内容”。

### 验证（这次仍然靠数值 + 截图，不靠“测试全绿”下结论）

- vitest **285/285** · 冒烟 **61 项全过** · typecheck ✓ · build ✓
- 浏览器探针数值 + 截图双证据：
  - 连线锚点相对列头的屏幕偏移**精确等比**：100% 765px → 300% 2295px → 10% 76.5px；
    且中途拖动卡片后 10% 变为 68.36px = 76.5 −（81.37 平面px × 0.1），连线跟着卡片走
  - 缩放 2.458 下拖 200 屏幕像素 = **81.369** 平面像素（理论 81.37）→ `scale` 精确生效、无漂移
  - 网格 33px(300%) / 8.8px(10%)；无控制台错误
  - 截图确认 300% 文字清晰、10% 为干净点阵总览（2.2px 摩尔纹已由自适应步长消除）

### 明示的对价

- 滚轮不再是平移（平移改由拖拽承担）；缩放/平移仍不进工作区快照。
